01 // PROJECT OVERVIEW

End-to-end SOC automation

For this project I created an end-to-end SOC automation lab designed to simulate how a modern security team detects, enriches, investigates and manages endpoint security alerts.

This environment uses a Wazuh as the SEIM/EDR platform, Sysmon for a detailed windows telemetry, Shuffle as the SOAR orchestration layer, VirusTotal for threat-intelligence enrichment and TheHive for a detailed case management and analyst investigation.

These security events that generated on the windows endpoint are collected by the Wazuh and forwarded to the Shuffle through a webhook integration. Next shuffle processes the alert and performs the enrichment where applicable and creates the alert in the TheHive for investigation. The analyst (Me) validates the detection, reviews the process and the endpoint for further context, ultimately this determines whether containment is required and had made the final verdict.

This lad was validated by using multiple detection scenarios including malicious-file activity, suspicious PowerShell execution and suspicious file creation associated with PowerShell. The primary case study focuses in the Suspicious File creation by PowerShell that was investigated and closed as a True Positive authorised lab event no actual impact.

03 // WORKFLOW

Alert orchestration in Shuffle

The workflow begins when the Wazuh forwards the security alert to Shuffle through a webhook integration. Shuffle then processes the alert and routes it through automation workflow.

Then where applicable the alert is enriched by using the VirusTotal to provide additional threat intelligence. This is based on the workflow conditions that relevant alerts are the sent to TheHive where they are created as investigation alerts for analyst to review.

The analyst I reviewed the alert inside TheHive validates the detection, proceeds to investigate the endpoint and process context which determines whether containment is really required and make the final verdict.

WAZUH ALERT→SHUFFLE→VIRUSTOTAL→THEHIVE→ANALYST

07 // LESSONS LEARNED

Troubleshooting the integrations

During this project, I encountered several integration and configuration issues that helped me better understand how the different SOC platforms communicate with each other.

WEBHOOK

Webhook integration

I learned how Wazuh forwards JSON alerts to Shuffle through a webhook and how incorrect integration settings can prevent alerts from reaching the SOAR workflow.

AUTH

API authentication

While connecting Shuffle to TheHive, I encountered authentication and permission errors. I resolved these by configuring the correct API key, organisation permissions and service-user profile before Shuffle could successfully create alerts.

THEHIVE

Duplicate alerts

I learned that TheHive requires each alert to have a unique sourceRef. When I reused the same reference, I received duplicate-alert errors, so I began using unique references for each test alert.

TUNNEL

Cloudflare tunnel changes

Because I was running TheHive inside my local lab, I used a Cloudflare Quick Tunnel to make it reachable by Shuffle. I learned that the tunnel URL changes whenever it restarts, which meant I also had to update the TheHive authentication URL inside Shuffle.

VT API

VirusTotal enrichment

I learned how to extract a file hash from a Wazuh event, submit it to the VirusTotal API and use the returned malicious detection count as part of my workflow decision logic.

ANALYSIS

Alert accuracy

I learned that I should not automatically treat every event as malicious. Reviewing the original Sysmon and Wazuh data helped me determine whether activity was genuinely suspicious or simply authorised lab or system activity.

CASE MGMT

Case management

Using TheHive helped me understand the importance of documenting validation, investigation findings, containment decisions and my final verdict rather than simply closing an alert.

KEY TAKEAWAY

The biggest lesson I learned from this project was that SOC automation is not simply about connecting tools together. I found that reliable automation depends on correct authentication, data formatting, permissions, workflow conditions and human validation so alerts can be handled accurately.
